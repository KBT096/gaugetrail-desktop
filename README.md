## 0. 先和大家打个招呼吧 👋

### 你是谁？

我是 **KBT096**，GaugeTrail Desktop 的发起人、作者和维护者。

我没有想把这个 Demo 写成一套“什么都能做”的大型质量平台，也不想把统计结果包装成神奇的 AI 结论。这个项目最初的念头其实很简单：

> 当一列测量数据开始变得不对劲时，电脑能不能先把值得注意的地方讲清楚，再让人决定下一步？

表格很擅长存数字，却不一定会告诉我们某个点为什么值得检查；控制图很有用，但第一次接触的人常常先被术语挡在门外；专业软件能力很强，却未必适合每一次临时分析和小规模验证。

于是就有了 GaugeTrail Desktop。它把一列测量值放进一个原生 Windows 窗口里：数据在左边留下时间、批次和来源，图表在中间呈现变化，规则信号在右边说明“为什么被标记”，后续行动再沿着状态一步步留下记录。

### 你是怎么用 Codex 把 Demo 做出来的？

我先给 Codex 看了一套优秀 SPC 项目的展示方式：不要只罗列技术名词，要把“谁会用、为什么做、怎样体验、哪里踩过坑”讲成一段读得下去的故事。

但真正开始开发时，我们没有照搬它的 Web 架构，也没有复制它的功能数字。我们重新做了几个取舍：

1. **从 Web 改成 Windows 原生桌面端**：数据原本就常在 Windows 和 Excel 旁边，双击应用比部署服务更直接。
2. **从“大而全”改成“一条路径走通”**：首版只做好连续测量值、I 图、过程能力、规则解释和行动闭环。
3. **先写边界，再写功能**：控制限不是规格限，统计信号不是根因，Demo 也不等于通过行业认证。
4. **用可重复验证代替口头保证**：核心算法、CSV、JSON、报告和异常输入都进入自测，桌面窗口也在真实 Windows 环境启动检查。

开发过程中经历了“先能算、再能看、最后让人读得懂”的几轮调整。比如第一版演示数据触发了 33 条信号，数学上并非错误，但连续滑动窗口造成了明显的信息噪声。最终改成：同一规则连续命中的重叠窗口合并为一次事件，同时保留首次触发窗口的最后一点。

这正是 GaugeTrail 想表达的原则：**工具不是为了显得聪明，而是为了让判断更清楚。**

## 1. Demo 简介

### 1.1 它是什么？

GaugeTrail Desktop 是一款面向 Windows 的离线过程数据分析 Demo。它把“记录—分析—解释—行动—验证”串成一条本地工作流：

```mermaid
flowchart LR
    A[手工记录 / CSV] --> B[本地工作区]
    B --> C[I 图与过程能力]
    C --> D[8 条透明规则]
    D --> E[解释卡片]
    E --> F[六阶段行动闭环]
    F --> G[Markdown / CSV / JSON]
```

- **零账号**：不用注册，也没有登录页面；
- **零后端**：没有服务器和数据库服务；
- **零上传**：应用本身不包含网络请求；
- **开箱体验**：首次启动自动载入 58 条演示测量记录；
- **原生桌面**：使用 C#、.NET 8 和 WPF，不是网页套壳。

### 1.2 面向谁？

| 用户 | 可以怎样使用 |
|---|---|
| 质检员 / 班组人员 | 手工补录少量测量值，快速查看是否出现明显信号 |
| 质量工程师 | 导入 CSV，查看 I 图、控制限、Cp/Cpk/Pp/Ppk 与规则证据 |
| 工艺工程师 | 根据时间和批次定位偏移、趋势或特殊原因点 |
| 学生 / 初学者 | 用内置数据理解中心线、控制限、规格限和规则窗口的区别 |
| 小团队 | 把一次异常调查推进到验证、关闭，并导出 Markdown 快照 |

### 1.3 核心亮点

1. **Windows 原生离线体验**
   下载 ZIP、解压、双击 EXE 即可使用。发布包为 Windows x64 自包含版本，不要求单独安装 .NET Runtime。

2. **每条信号都能解释**
   信号包含规则编号、规则名称、触发时间、测量值、窗口证据和通俗说明，不只显示一个红点。

3. **重叠窗口自动合并**
   对 R2–R8，同一规则连续命中的滑动窗口合并为一次事件，标记首次触发窗口末端，减少重复告警。

4. **过程能力与规格分开呈现**
   控制限由当前数据估计；LSL、Target、USL 由用户设置。界面不会把两者混成同一件事。

5. **六阶段行动闭环**
   `待确认 → 已确认 → 调查中 → 已采取措施 → 待关闭 → 已关闭`。进入待关闭前必须填写验证备注。

6. **本地数据可带走**
   测量值可导出 CSV，分析结果可导出 Markdown，完整工作区可导出 JSON。

### 1.4 主要功能

| 模块 | v0.1.0 已实现 |
|---|---|
| 过程总览 | 数据点、均值、Cpk、规则信号、解释卡片、最近信号 |
| 趋势图 | 单值 I 图；中心线、控制限和规格限同图展示 |
| 波动估计 | 移动极差均值 `MR̄ / 1.128` 估计过程内 σ |
| 过程能力 | Cp、Cpk、Pp、Ppk |
| 规则检测 | 8 条公开规则，保留具体窗口证据 |
| 数据管理 | 手工记录、CSV 导入、错误行隔离、合并去重 |
| 行动闭环 | 从信号创建行动项、负责人、验证备注、六阶段状态 |
| 审计记录 | 记录导入、设置与行动状态变化 |
| 本地保存 | JSON 原子替换保存，并保留最近一次 `.bak` |
| 报告导出 | CSV、Markdown、完整工作区 JSON |

## 2. Demo 创作思路

### 2.1 灵感来源

很多数据分析并不是从一套完美系统开始的，而是从桌面上的某个表格开始：

- 一列时间；
- 一列测量值；
- 旁边可能还有批次和备注；
- 某一天，有人觉得“最近好像越来越高了”；
- 然后大家开始翻文件、画图、问这是不是异常。

真正困难的地方往往不是算出均值，而是把三个问题接起来：

1. **哪里值得注意？**
2. **为什么值得注意？**
3. **注意到以后做了什么？**

因此，GaugeTrail 没有把首页做成一堆复杂配置，而是直接放入一组带有平稳段、持续偏移和特殊原因点的演示数据。第一次打开，就能看到数字怎样变成线、线怎样触发规则、规则怎样变成行动项。

### 2.2 想解决的问题

| 常见困境 | 传统处理方式 | GaugeTrail Desktop 的选择 |
|---|---|---|
| 数据散落 | 多个 Excel 文件来回查找 | 一个本地 JSON 工作区，保留时间、批次、来源和备注 |
| 图画出来却难解释 | 只看红点或超限 | 每条信号都给出规则名称、窗口和证据 |
| 滑动窗口重复告警 | 同一趋势连续刷屏 | 将连续重叠窗口合并为一次信号事件 |
| 规格限与控制限混淆 | 两条线都叫“上下限” | 规格由人设置，控制限由数据估计，使用不同颜色 |
| 发现异常后没有下文 | 在聊天或纸上临时记录 | 从信号直接创建六阶段行动项 |
| 报告难复用 | 截图、复制粘贴 | 一键生成带边界说明的 Markdown 快照 |
| 不希望上传生产数据 | 在线工具需要账号或服务 | 默认完全离线，本地保存，无网络请求 |

### 2.3 为什么选择电脑端？

参考项目采用浏览器离线方案，而 GaugeTrail 选择了另一条路线。

在我们的设想里，测量数据通常刚从 Excel、量具导出文件或桌面文件夹里出来。原生电脑端可以自然地支持文件对话框、CSV 拖放、本地目录和自包含 EXE，同时避免用户误以为数据正在通过网页发送到某个服务器。

这个选择也意味着首版只服务 Windows 10/11 x64，不追求跨平台。对 v0.1.0 来说，**把一个平台做好并讲清楚，比同时画出三个平台的路线图更重要。**

### 2.4 我们主动放弃了什么？

为了让初代版本真实可用，我们没有在 README 里写入尚未实现的“大功能”：

- 没有伪装成 AI 根因诊断；
- 没有多用户、云同步和权限审批；
- 没有 Xbar-R、Xbar-S、P、NP 等其他控制图；
- 没有正态性检验和置信区间；
- 没有宣称通过 AIAG、VDA 或其他行业认证；
- 没有把演示验证描述成生产环境验证。

这些内容以后可以逐项增加，但 v0.1.0 的边界必须先说清楚。

## 3. Demo 体验

### 3.1 推荐体验方式

前往 [最新 Release](https://github.com/KBT096/gaugetrail-desktop/releases/latest)，下载：

```text
GaugeTrail-Desktop-v0.1.0-win-x64.zip
```

然后：

1. 解压 ZIP 到任意可写目录；
2. 双击 `GaugeTrail.Desktop.exe`；
3. 首次启动会自动载入“A 线 · 轴套外径”演示工作区；
4. 不需要管理员权限，不需要数据库，也不需要联网。

> Windows SmartScreen 可能会提示这是尚未积累信誉的新应用。v0.1.0 暂未购买代码签名证书；请只从本仓库 Release 下载，并核对 Release 中公布的 SHA-256。

### 3.2 五分钟体验路径

| 步骤 | 页面 | 建议体验 |
|---:|---|---|
| 1 | 过程总览 | 查看 58 个数据点、I 图、Cpk、规格限和红色特殊原因点 |
| 2 | 规则信号 | 选择一条信号，阅读规则说明与窗口证据 |
| 3 | 行动闭环 | 从所选信号创建行动项，填写负责人并推进状态 |
| 4 | 测量数据 | 手工补录一个数值，或拖入 `examples/sample-line.csv` |
| 5 | 报告与导出 | 导出 Markdown 快照，查看统计摘要、信号和解释边界 |
| 6 | 工作区设置 | 修改指标名、单位与规格限，观察 Cpk 和图表重新计算 |

### 3.3 CSV 格式

必需列为 `timestamp` 和 `value`；其余列可选：

```csv
timestamp,value,batch,source,note
2026-08-21 08:00:00,10.02,B-01,数字千分尺,首件复核
2026-08-21 08:20:00,10.08,B-01,数字千分尺,
```

也支持中文表头，以及逗号、分号或 Tab 分隔。错误行会被隔离并说明原因，不会因为一行错误让整份文件失效。

### 3.4 数据保存在哪里？

默认工作区：

```text
%LOCALAPPDATA%\GaugeTrail\workspace.json
```

最近一次旧版本：

```text
%LOCALAPPDATA%\GaugeTrail\workspace.json.bak
```

如果现有 JSON 无法读取，应用会只在内存载入演示数据，并保留原文件，不会悄悄覆盖。

### 4.1 开发中的踩坑与解决办法

| 踩坑 | 表现 | 解决办法 |

| WPF 默认颜色没有完整继承 | 部分数字在深色卡片上变成黑色 | 增加全局 TextBlock 前景色，并给根窗口显式设置背景 |

## 5. 核心功能详解

### 5.1 I 图与过程内波动

数据按时间排序后绘制单值 I 图：

- 中心线 `CL = 平均值`；
- 相邻点计算移动极差；
- 过程内标准差 `σwithin = MR̄ / 1.128`；
- 控制上限 `UCL = CL + 3σwithin`；
- 控制下限 `LCL = CL - 3σwithin`。

首版没有单独绘制 MR 子图，因此更准确的描述是“**使用移动极差估计波动的 I 图**”，而不是宣称已经完成所有 I-MR 交互。

### 5.2 过程能力

当 LSL 和 USL 均有效时，系统计算：

- `Cp`：规格宽度相对于过程内波动的潜在能力；
- `Cpk`：同时考虑均值偏移的过程内能力；
- `Pp`：使用整体样本标准差的总体表现；
- `Ppk`：同时考虑均值偏移的总体表现。

界面不会仅凭 Cpk 给出“合格/不合格”结论。样本不足、分布形态、抽样方式和客户要求都会影响正式判断。

### 5.3 8 条透明规则

| 编号 | 触发条件 |
|---|---|
| R1 | 单点越过 ±3σ |
| R2 | 连续 9 点位于中心线同侧 |
| R3 | 连续 6 点严格单调上升或下降 |
| R4 | 连续 14 点交替升降 |
| R5 | 连续 3 点中至少 2 点越过同侧 2σ |
| R6 | 连续 5 点中至少 4 点越过同侧 1σ |
| R7 | 连续 15 点全部落在 ±1σ 内 |
| R8 | 连续 8 点全部落在 ±1σ 外，且跨中心线两侧 |

R2–R8 的连续重叠窗口会被合并。规则名称和窗口长度在代码、界面与 README 中保持一致，方便复核。

### 5.4 行动闭环

规则信号可以直接转成行动项：

```text
待确认 → 已确认 → 调查中 → 已采取措施 → 待关闭 → 已关闭
```

负责人和验证备注保存在本地。系统要求“已采取措施”进入“待关闭”前填写验证备注，避免把“做过事情”直接等同于“已经有效”。

### 5.5 可审计导出

Markdown 快照包含：

- 当前状态和通俗解释；
- 均值、中位数、σ、控制限和能力指数；
- 规则信号及窗口证据；
- 行动项和状态；
- 明确的解释边界；
- 作者 `KBT096` 与 `MIT` 许可证信息。

## 6. 技术架构

```text
GaugeTrail.Desktop (WPF / Windows UI)
        │
        ├── ControlChartView     自绘控制图
        ├── MainWindow           页面、文件对话框、交互流程
        │
GaugeTrail.Core (.NET 8)
        ├── StatisticalAnalyzer  统计量与能力指数
        ├── RuleEngine           8 条规则与窗口合并
        ├── CsvMeasurementService
        ├── WorkspaceStore       JSON 原子保存与备份
        └── MarkdownReportBuilder
```

- 语言：C# 12
- 桌面框架：WPF
- 目标框架：.NET 8
- 第三方运行时依赖：无
- 本地数据：System.Text.Json
- 图表：WPF `DrawingContext` 自绘

### 从源码运行

需要 Windows 和 .NET 8 SDK：

```powershell
dotnet build GaugeTrail.sln -c Release
dotnet run --project src/GaugeTrail.Desktop/GaugeTrail.Desktop.csproj -c Release
```

运行自测：

```powershell
dotnet run --project tests/GaugeTrail.SelfTest/GaugeTrail.SelfTest.csproj -c Release
```

## 8. 当前限制与后续方向

### v0.1.0 当前限制

- 仅支持连续数值型测量数据；
- 只有一个活动工作区；
- 只提供使用移动极差估计的 I 图；
- 没有正态性检验、置信区间或分布拟合；
- 没有用户权限、电子签名和多人协作；
- 应用未购买 Windows 代码签名证书；
- 规则集需要组织在正式使用前自行确认。

### 可能的后续版本

- 多工作区与归档恢复；
- 独立 MR 图、Xbar-R / Xbar-S；
- 规则启停和规则集版本记录；
- 数据质量诊断与重复测量识别；
- 可复核的 HTML/PDF 报告；
- 更完整的键盘操作和无障碍说明。

路线图不是承诺。功能会在有真实使用反馈和可验证实现后进入 Release。
